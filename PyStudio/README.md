# PyStudio — Browser Python IDE

PyStudio is a static website for writing and running Python in the browser. It uses CodeMirror 6 for editing and Pyodide (CPython compiled to WebAssembly) inside a dedicated Web Worker. Python source is not sent to an execution backend. Projects are stored in the browser with IndexedDB.

## Local development

Run the included development-only static file server:

```bash
python3 dev-server.py --host 127.0.0.1 --port 8000
```

Then open `http://localhost:8000`. This helper only serves HTML, CSS, JavaScript, and static assets; it never executes Python submitted in the IDE. Python programs run inside Pyodide in the browser. You can also use another static HTTP server, but it must provide cross-origin isolation headers or allow the included COI service worker to do so. Opening `index.html` using `file://` is not supported.

The first visit may reload once while `coi-serviceworker.js` installs isolation support. Keep that same-origin service-worker file in the published folder; do not load it from a third-party CDN. The app downloads CodeMirror and Pyodide from pinned public CDNs, so the browser needs network access on first use. Pyodide's compatible package installer downloads package files from PyPI.

## Install on a phone

Serve PyStudio over HTTPS (or localhost during development), then open it in a supported mobile browser. On Android, tap **Install** in the top bar when it appears, or use the browser menu and choose **Install app** / **Add to Home Screen**. On iPhone or iPad, open the page in Safari, tap **Share**, choose **Add to Home Screen**, then confirm with **Add**. The installed app uses the PyStudio launcher icon, standalone display, and matching dark theme colors. The worker caches same-origin app assets and can show an offline notice, but CodeMirror and Pyodide are loaded from public CDNs; offline opening does not guarantee that Python can run without a network connection.

## Deploy to Cloudflare Pages

1. Connect the repository to Cloudflare Pages, or upload the static project files.
2. Select no framework preset, set the build command to `true`, and use `public` as the output directory (or leave the command empty if using Cloudflare Pages' dashboard directly).
3. Keep `_headers` in the published output root. It adds `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp`, which enable the SharedArrayBuffer bridge required for interactive stdin and worker interrupts.
4. Deploy over HTTPS. If you change the library CDNs or security policy, check the browser console for blocked cross-origin resources.

Cloudflare Pages reads `_headers` from its static output. If you later add Pages Functions, configure the same headers on those Function responses too; `_headers` does not modify responses generated by Functions.

## Deploy to GitHub Pages

1. Push the project files to a GitHub repository.
2. In the repository's **Settings → Pages**, choose the `main` branch and `/ (root)` (or the published folder that contains `index.html`).
3. Open the published HTTPS page. GitHub Pages does not provide a repository `_headers` mechanism, so the included, self-hosted `coi-serviceworker.js` adds cross-origin-isolation headers to navigations. The first load can reload once after registering the service worker. Do not remove the script or move it to a third-party CDN.
4. For a project site under `https://USER.github.io/REPOSITORY/`, keep the relative URLs in the HTML and serve the worker/service worker within that same path.

The `_headers` file is specific to Cloudflare Pages; the self-hosted service worker is included for hosts that cannot configure response headers. For another static host, either send both headers on the document responses (`COOP: same-origin`, `COEP: require-corp`) or use a compatible, self-hosted service-worker isolation shim over HTTPS.

## Features

- CodeMirror 6 with Python support, line numbers, indentation, completion, bracket matching, folding, search, multiple file tabs, and keyboard shortcuts.
- Pyodide Web Worker with captured standard output/errors, real `input()` through the integrated terminal, interruption/timeout recovery, and compatible `micropip` installation.
- IndexedDB projects/files with autosave, restore, create, rename, delete, import, switching, and downloads.
- Terminal history, ANSI colors, copy/download/clear controls, execution timing/status, and mobile-friendly interactive input.
- Resizable editor/terminal panels on desktop, Editor/Terminal tabs on mobile, dark/light themes, examples, help, and beginner exercises.

## Important limitations

Cross-origin isolation is required for the shared-memory stdin bridge and interrupt buffer. If `crossOriginIsolated` is false, the app disables execution and explains how to enable it rather than falling back to `prompt()`. Pyodide packages that need native extensions unavailable in WebAssembly will not install. Browser-based execution is not a complete security sandbox: untrusted Python can use CPU and memory, and Pyodide exposes browser-adjacent and network-capable APIs. Each run has a 30-second limit, terminal history is capped at 250,000 characters, and Stop/timeout terminate and recreate the Worker. Browsers do not expose a portable hard per-worker memory quota. Only run code you trust. Projects are local to the current browser profile and are not synced or backed up automatically.

Keyboard shortcut: **Ctrl/⌘ + Enter** runs the current file. In the terminal, Enter submits a Python input line and the up/down arrows recall previously submitted inputs.
